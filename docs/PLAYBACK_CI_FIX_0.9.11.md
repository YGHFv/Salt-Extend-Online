# 播放与后台测试窗口修复 0.9.11

## 复现与原因

2026-11-13 用户反馈开发测试窗口突然置顶、随后自行消失，同时部分 QQ 歌曲双击后显示 `Online resolution failed (IOException)`。

本机 self-hosted GitHub Actions 日志显示 14:32:36–14:35:16 执行过打包作业，其中完整回归步骤为 14:33:11–14:35:05。`PlaybackVideoPacingTest` 和 `PlaybackVideoRenderTest` 在自动矩阵内创建可见 `ComposeWindow`、设置 `alwaysOnTop`；后者还调用 `toFront`、`requestFocus` 和 Robot 鼠标操作，结束后销毁窗口。隐藏 runner 控制台不能阻止测试创建这些窗口。Salt 启动日志中的 `--workshop-publisher` 是另一个启动参数，不能据此解释用户反馈的测试窗口。

通过插件自身保存的 QQ 登录只读复现歌单播放，前三个明确失败项是《一番星（第一颗星）》《恋ひ恋う縁（以恋结缘）》《鳥の詩（鸟之诗）》。详情中的 `size_flac=0` 导致跳过无损档，`O800` 高音质 vkey 成功，但两个官方 CDN 都返回 HTTP 404。旧代码把非 206 响应归为普通 IOException，并在第一个节点失败时结束整次解析，未继续已有的音质降级流程。

## 修改

- QQ Range 探测保留 4xx/5xx 的数值状态，其他平台的备用节点策略保持原有行为。QQ 只对 404/410 尝试本次官方 `sip` 给出的去重节点，全部缺失后继续官方编码／音质候选。
- 参考 NeriPlayer、mygo-qyin 和 MusicOne 的 HQ 映射，补充 `M800` 320 kbps MP3。先尝试同档 `O800` 和 `M800`，再降至较低音质；MP3 独立校验 `size_320mp3`，保留 `exhigh` 音质标识，不扩展 UI 音质枚举。
- 授权、风控、服务故障以及长度、签名、媒体身份异常保持失败，不把错误响应当作音频，也不接受试听替代。
- 单曲与合集共用安全错误分类。单曲显示例如 `音轨加载失败 [MEDIA_HTTP=404]`，不再丢失 QQ/API/媒体失败阶段。
- QQ 无专辑单曲补读 `vs[1]` 的歌曲图片 MID，对应官方 `T062` 图片；只接受严格校验的图片标识。《未闻花名》的歌单与歌曲详情都使用这一封面。列表与播放封面共享同一图片身份的官方静态 CDN 备用地址。
- 视频时钟、离屏 UI、原生解码控制与销毁检查继续自动执行。置顶窗口、屏幕截图与真实鼠标测试默认跳过，只有本地构建显式传入 `-InteractiveDesktopTests` 才启用；CI 额外禁止该模式，Gradle 检查显式关闭它。

## 实际歌曲验证

整张 85 首歌单中 84 首通过正式音频 Range 校验：68 首无损、14 首 HQ、2 首标准音质。洛天依／乐正绫版《锦鲤抄》（`001miTCi0c1T7V`）的当前账号请求仍返回 `QQ_TRACK_UNAVAILABLE=104003`。补充 `M800` 后以及对照参考项目的官方请求形式、文件布局后仍未取得这首歌的 QQ HQ 音轨。用户反馈 HQ 可以播放，因此此项保留为待对照实际可播放客户端／会话的未解决差异，不能据此认定歌曲已下架或账号无权限。没有修改用户的自动换源设置，也不以备用音源能播放作为 HQ 修复完成的证据。

QQ 自动合同新增节点缺失、重复节点、同档 MP3 后备、音质降级、全部缺失以及授权/服务/长度异常不得继续的用例；无专辑封面、非法图片标识、专辑优先和 CDN 图片缓存也有回归。单曲与合集分别检查错误分类和凭据脱敏。回归执行器检查默认禁用桌面模式、覆盖继承的 JVM 开关、CI 拒绝交互模式、超时终止和配置隔离。交互式桌面测试本轮未运行。
