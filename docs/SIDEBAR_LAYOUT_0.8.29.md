# 0.8.29 顶部侧栏布局与原色图标

## 两层问题

0.8.27 使用替换 hook，宿主对非零默认参数 mask 跳过替换，导致增强完全不显示。0.8.28 本机验证版改为追加 hook 后内容开始执行，但仍位于宿主标题栏左侧固定宽度区域中，因此后半部分被裁掉；只检查内容测量宽度不足以确认它真正可见。另外，图标内容没有居中，统一 tint 也把原有彩色 PNG 变成了单色。

## 修复方式

- 两个独立官方 `afterComposable` 插槽：切换按钮后只放零尺寸位置探针；整个 MainTitleBar 后在窗口根 Box 中显示图标栏。后者不受原有约 260 dp 左区域裁切。
- 图标栏位置取原生切换按钮实际 `positionInRoot`，扣除窗口根坐标后放到其右侧；尺寸使用原生 caption 的高度／宽度，图标在按钮内水平与垂直居中。
- 删除统一 tint，Windows 原生图标保留资源本来的颜色；本来是单色的图标仍为单色。Bilibili 和网易云保留品牌色。
- 保留全部 10 个原生操作、两个在线平台、本地歌单入口。足够宽时全部横向显示，窄窗口使用横向滚动，不把后面的操作丢弃；保留右侧窗口控制区。
- 关闭功能、展开原生侧栏、退出常规标题栏或者撤销权限时移除追加内容，不替换原生按钮，不改动歌单或播放队列。

## 回归范围

增强测试包含真实宿主转换后的 caption 调用，原调用默认参数 mask=880 未改；另一个窗口级插槽也通过实际 resolver／转换器验证唯一性。离屏布局显式模拟左侧 260 dp 裁切，并让顶部图标栏作为它的兄弟节点。

测试覆盖 1280／520 宽度、收起／展开、两个平台和各个原生入口、歌单更新、选中态、权限、按钮与图标中心位置、后半部按钮越过原左区域后的可见边界。像素检查使用合成测试界面，确认原生彩色图标及两个品牌图标没有被灰化；不读取用户截图，也不输出图片内容。

设置键保持 `ui.sidebarOptimization`，沿用已有开关值。

## 本机窗口验证

2026-11-08，安装 0.8.29 并重启后，通过运行进程的 Compose 语义节点检查（无截图）：

- 原生切换按钮边界 `(96,17)-(166,73)`；Bilibili `(586,17)-(656,73)`；网易云 `(656,17)-(726,73)`，两平台完整宽度与原生按钮相同，上下边界一致。
- 调用原生切换按钮回调后，侧栏展开、顶部平台按钮移除；再次调用后收起，平台按钮恢复相同位置。
- 图标区域实际测量宽度 910 像素，运行诊断 `sidebar=true/rendered=17/width=910`，没有只注册不绘制的问题。
- 最终保持原本的收起状态，不点击歌曲、不修改播放队列或歌单。

完整 62 个测试入口、84 次宿主／基础运行通过；新增侧栏专项 166 项检查。安装包全部 294 个条目与测试输出逐项一致。
