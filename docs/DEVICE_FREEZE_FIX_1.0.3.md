# 1.0.3 本机卡死与生命周期修复

## 现场原因

2026-11-13 在本机运行的 Salt 1.19.3／模组 1.0.2 上采集线程和运行状态。模组已完成初始化，AWT 事件队列能处理哨兵任务，两个 Compose 重组器没有保存异常。因此当前现场不是已经捕获到的网络断开阻塞或重组协程异常取消。

进一步读取实际 HWND 的 WndProc 和 JNA 回调表，发现当前 `ComposeWindowProc`、`SkiaLayerWindowProc` 的前驱地址均没有对应的活 Java 回调。任务栏回调仍指向当前窗口回调；窗口命中测试返回正常 `HTCLIENT`，消息转发链的下一层却已经失效。

Salt 自带 `BasicWindowProc` 在构造时用 `SetWindowLongPtr` 安装回调，仅以 `LONG_PTR` 保存前驱地址。JNA 的 callbackMap 使用弱引用，原生地址本身不会保留 Java 对象。窗口框架在重组、安装或卸载钩子时再次建立消息回调，旧对象离开组合后可能被 GC，导致当前回调继续向失效地址转发。这解释了后台播放／事件队列正常、窗口点击失效的现场表现。

0.9.10 的窗口框架 after 钩子继续保留。但已有测试仅检查创建窗口之前已完成字节码转换、随后切换钩子内容的状态，不能覆盖所有真实宿主安装顺序，亦未验证强制 GC 后前驱对象是否存活。

现在在启动、UI／视频钩子安装及卸载之前保存现存的宿主消息回调，窗口框架的后置观察继续保存当前链。回调根据原生窗口／画布的 HWND 归属保存在对应 `JRootPane` 的 JDK Map 中，以指针去重；不把模组监听器、闭包或插件类实例放进此存储。窗口因此可以跨 PF4J 加载器关闭保留消息链，窗口对象销毁后存储一起释放。已经被回收的旧对象不能恢复，需要完整退出并重新启动宿主。

## 同类路径检查与修复

- 检查所有 Kotlin `DisposableEffect` 清理、UI／视频钩子、原生音频回调所有权、后台启动与停止、封面／平台请求取消、Range 传输及缓存维护。保留已存在的侧栏清理直接遍历、异步断开连接、BASS 句柄由宿主管理和终止回调门禁。
- `SaltVideoSurface.close()` 原来在 Compose 清理线程等待 GPU 读取锁，并同步释放 mpv 画面。现在先逻辑关闭，读取执行器将释放任务排在已有读取之后；AWT 图片仍由界面线程释放。播放器句柄在所有画面释放完成后后台销毁，已从 Compose 移出的画面的待完成释放也纳入等待。相同播放器重建画面时，新读取先等待旧画面释放，避免旧清理释放新画面。
- 磁盘 Range 缓存原来在读写／删除时持有缓存锁。界面发起的上限调整、清理、撤销和停止现在按每个传输实例在后台串行处理磁盘操作；逻辑撤销、连接取消及监听服务关闭立即执行。后台上限调整不再持有传输服务锁等待缓存锁，避免把等待传递给界面上的注册／撤销。退出会排空维护任务并关闭执行器。`java.base` 无宿主用法及后台调用的同步语义保留。
- Range 请求已关闭时附加连接的失败分支也改为异步断开，不在请求锁内执行可能等待 TLS 的清理。

## 回归方式与边界

`NativeWindowCallbackRetentionTest` 使用 Salt 真实 `BasicWindowProc`、真实 HWND 和无焦点的桌面外 1×1 窗口建立双层转发链。丢弃旧 Java 变量后反复强制 GC，确认前驱仍然存活，再用带超时的私有消息验证消息穿过两层回调；验证存储去重及窗口销毁。没有回调保留时，同一测试在发送消息之前因前驱被回收而失败，避免故意调用已释放的原生地址。

`VideoSurfaceRetirementTest` 使用生产 `SaltVideoSurface.close()`，受控任务占住 nativeLock 并忽略中断，再分别阻塞画面释放。确认 Compose 清理及后续 AWT 任务都能返回；确认读取结束前不释放画面、画面释放结束前不销毁句柄、重复关闭只释放一次、读取执行器退出。对比 1.0.2 的同步关闭实现，同一测试因清理等待读取锁而失败。

`CacheUiResponsivenessTest` 占住真实缓存监视器，模拟后台慢磁盘操作，再在 AWT 调整上限、清理、注册／撤销和停止。确认界面无需等待缓存监视器，逻辑撤销立即生效，释放阻塞后维护执行器完成清理并退出。1.0.2 的同一测试因界面等待缓存锁而失败。

完整构建测试清单为 99 个入口，继续覆盖宿主 UI ABI、PF4J 卸载清理、封面请求取消、音频／视频 Range 缓存、播放生命周期和诊断日志隐私。新增阻塞回归使用受控夹具；不能把这些夹具视为额外捕获了用户现场的 GPU 或磁盘阻塞。窗口回调失效来自本次真实进程读取；其他路径来自代码检查及可重复的阻塞测试。默认未运行前台视频帧率和真实鼠标操作检查。
