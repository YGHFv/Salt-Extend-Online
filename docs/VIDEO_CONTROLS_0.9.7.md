# 0.9.7 视频控件与播放页交互

此版本的视频初始化存在宿主兼容错误，导致视频按钮消失。以下记录
描述当时的实现意图；修复和当前验证方式见 [0.9.8](VIDEO_HOOK_FIX_0.9.8.md)。

视频模式下，鼠标静止 3 秒后，底部播放控件、播放页标题栏、视频切换
按钮以及右上角的全屏、最小化、最大化、关闭按钮一起隐藏；移动鼠标
或进行操作时恢复。窗口按钮位于独立的窗口装饰层，需要使用同一份
可见状态，并在隐藏时清空 Windows 原生按钮的命中区域。
视频收起后窗口按钮恢复原生主题；再次展开时恢复视频按钮颜色和计时。

左键单击视频画面调用 Salt 的 `PlaybackController.playOrPause()`。
视频仍然静音并跟随歌曲的播放状态、进度和速度。右键、拖动及点击
播放控件不会触发画面的单击操作。

视频现在替换原生播放页容器内的封面／歌词内容。底部 MiniPlayer
留在 Salt 原来的调用位置，保留原始布局、主题参数和整页展开／收起
回调；移除额外的 24dp 底部间距和独立视频播放条。点击播放条背景
不会切换回封面／歌词，而是沿用原生整页收起功能。重新展开时保留
视频会话，容器原有的展开、折叠和收起动画继续由 Salt 管理。
视频使用原生播放页的透明度动画，收起后隐藏画面和画面点击区域。

视频展开时移除独立绘制的浮动封面及其命中区域，避免透明封面挡住
视频单击；展开后的标题内容只隐藏绘制，保留布局尺寸。播放页与
播放条的宿主调用带有非零默认参数掩码，改用方法钩子接入，完整
保留默认参数和 Compose 重组。

回归检查覆盖真实宿主方法变换、原生播放页布局、Direct3D 窗口、
窗口按钮与播放控件的隐藏恢复、画面单击与音视频暂停同步、右键和
拖动排除、底部布局位置、原生收起／展开、窗口缩放与视频故障退出。
测试使用本机合成视频、独立配置目录和内存音频状态，不依赖平台账号。

保留 0.9.6 的固定视频帧缓冲方案，窗口缩放不调用曾导致原生线程
卡住的退役缓冲确认接口。GitHub Actions 继续使用有单项超时和独立
日志的构建脚本，以及带守护进程的专用 Windows runner。
