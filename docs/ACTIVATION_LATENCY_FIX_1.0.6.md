# 1.0.6 私人雷达与启用延迟修复

## 私人雷达读取失败

网易云官方 `/api/v6/playlist/detail` 对私人雷达（3136952023）以及时光雷达等动态歌单返回的内联歌曲包含重复 `alg` 字段：先为 `null`，随后为算法字符串。匿名实际请求也能复现这一格式，原有严格 JSON 解析在歌曲映射之前拒绝整个响应，因此显示 `NET_CONTENTS/RESPONSE`。

歌单详情专用解析仅允许 `playlist.tracks[*]` 中 `alg:null` 后接字符串；不放宽其他路径或字段，不允许非空覆盖、第三次重复或非字符串覆盖。算法字段不参与播放授权。字节、深度与节点上限以及歌曲 ID 唯一性、详情批次和账号校验继续生效。推荐歌单接口现有 `creator` 兼容与该规则独立。

合成 55 首歌、前 10 首内联详情的账号歌单测试覆盖首页补齐、最后一页、完整队列、空列表，以及重复歌曲 ID 和非法重复字段拒绝；JSON 测试覆盖专用解析路径边界和通用解析拒绝。匿名 `CatalogLiveProbe --explicit-public-probe radar` 用于对照修复前后真实接口，不读取本机账号。

2026-11-16 实测：旧类文件请求官方接口返回 `NET_CONTENTS/RESPONSE`，修复后同一匿名探针成功加载 20 首可用歌曲。账号专属 55 首列表使用合成 HTTP 验证，未访问用户保存的登录凭据。`NeteaseCatalogCompatibilityTest` 通过 41 项，`BoundedJsonContractTest` 通过 62 项。

## 启用延迟原因

1.0.5 在权限未就绪时使用 1 秒间隔重试；即使已授权，安装平台界面之前还需要读取保存歌曲、检查播放能力、注册播放恢复钩子以及 Windows 媒体身份和开始菜单快捷方式。界面是否可用由整个任务完成决定，后续功能准备也被串在入口之前。

## 改动

- 最小初始化仅建立配置、账号控制器和平台列表状态。授权后立即尝试安装平台界面，不先扫描保存歌曲或注册系统媒体身份。
- 权限重试间隔改为 100 毫秒，最长等待仍为 60 秒；安装异常最多尝试 3 次。成功后关闭执行器，未授权时不安装钩子。
- 平台入口安装完成后，独立后台阶段再读取保存歌曲、检查播放能力、配置恢复钩子和视频绑定。Windows 媒体身份注册排在播放支持就绪之后。
- 后续准备不会一直持有插件界面操作使用的生命周期监视器。资源交接只做短时状态检查；播放支持就绪之前不会使用未完成的播放适配器。
- 停止先撤销实例与授权门禁，再在释放插件监视器后取消、排空后续准备，最后清理。后台被取消时仍能进入发布监视器丢弃结果，不会与停止形成锁顺序倒置；PF4J 关闭加载器之前排空任务。
- 从界面请求修复缺失入口时也调度后台安装，避免在 AWT 上执行完整反射／钩子安装。
- 诊断增加 `PLAYBACK_SUPPORT_READY`，可以区分界面已就绪和后台播放准备是否完成。

## 验证与边界

`DeferredPluginStartupTest` 使用生产的 `ExperimentalPlugin.start()`、真实 Salt 界面类和隔离配置，宿主权限／钩子使用合成夹具。阻塞播放恢复钩子时，平台界面仍先安装完成，状态入口和 AWT 哨兵可返回。通过 AWT 调用真实 `stop()`，确认支持任务取消、结果丢弃、钩子清理以及界面内容恢复。独立测试将支持任务阻塞后要求其在取消时重新获取插件监视器，检查停止不会保留该锁等它退出。

默认权限重试测试在第一次未授权检查后授予权限，要求下一次安装在 750 毫秒内完成；旧 1 秒间隔无法满足，100 毫秒间隔可满足。这里只测调度造成的等待，不把合成宿主的安装耗时当作所有电脑的启动耗时。

保留并重新运行旧卡死问题的回归：PF4J 先关闭加载器再销毁 Compose 侧栏、原生窗口前驱回调经强制 GC 后仍存活、封面取消不阻塞 AWT、视频画面与句柄异步退役、缓存维护与存储发布不阻塞界面，以及播放生命周期和原生界面渲染。Windows 消息回调保留和侧栏直接遍历清理继续使用原有实现。

实际冷加载仍需要类加载、配置读取和宿主钩子安装，不能承诺零毫秒。自动回归默认不打开前台视频窗口或控制用户鼠标；检查能证明受测等待链与历史故障没有复现，不能排除所有机器的驱动／宿主问题。

最终 1.0.6 通过 102 个合约、137 次宿主／基础模块运行及安装包隔离校验。启动检查为 28 项，封面检查为 199 项，私人雷达兼容检查为 41 项，JSON 边界检查为 62 项。中断的构建保留了已通过的 80 份合约日志，在相同已编译类和隔离目录中补齐其余运行；没有用旧安装包替代最终产物。
