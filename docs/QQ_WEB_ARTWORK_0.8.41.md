# QQ 网页登录、封面与图标修复 0.8.41

## 参考与边界

继续使用已固定的两个参考版本：

- NeriPlayer `fd7fdb757821fda7a62aee3a2b7cecf3a4b8bfe0`：官方网页 Cookie 来源、身份与密钥别名、账号资料字段、QQ 矢量图标。
- mygo-qyin `152d32d2a0ba49a3074b120030684a2d22d899cf`：鉴权成功但不返回 UIN 时使用凭据中的账号 ID，以及歌单封面的 `big_url`、`medium_url`、`default_url`、`small_url`。

不使用公开主页作为登录证明，不生成伪设备身份，不模拟 QIMEI，不绕过账号／会员权限。保留现有 QRC 逐字歌词和 0.8.40 的原生解码输入生命周期修复。

## 原因与改动

### 网页登录

1. 旧版将整个 PowerShell 辅助脚本放进 `-EncodedCommand`。当时仅 QQ 入口的编码正文已有 32128 字符，接近 Windows CreateProcess 的命令行上限；较长的现有合成测试入口实际报 `CreateProcess error=206`。不能据此断言用户截图中的通用 `QQ_WEB/RESPONSE` 一定就是此原因。新版把代码写入仅当前用户可访问的本次临时目录，命令行只编码短读取器。文件只有代码，账号 Cookie 仍通过匿名管道传递。
2. 旧版只观察首个 `y.qq.com` 页面会话，忽略回调替换页面与父域 `.qq.com` 身份 Cookie。新版在本插件创建的全新隔离 Edge 环境中使用 `Storage.getCookies`，只选择允许域的 QQ 音乐字段；官方页面返回后要求两次连续收集稳定，再关闭该隔离浏览器。
3. 旧版对所有辅助 Cookie 执行账号密钥的严格字符校验，任意分析 Cookie 都可能使整次导入失败。新版先选择 QQ 音乐相关名称，丢弃分析 Cookie 和普通 QQ 的 `p_skey`／`skey`，不放宽通用 Cookie 容器。
4. 归一化 `qqmusic_key`／`qm_keyst`／`musickey` 和 `qqmusic_uin`／`uin`／`wxuin`，去掉 QQ 身份的 `o000` 前缀；优先音乐域身份。`tmeLoginType` 优先；官方网页 `login_type=1` 对应 API 类型 2，网页类型 2 对应 API 类型 1。官方省略类型时按已观察到的 QQ／微信身份判定，不盲目轮询另一种类型。
5. 账号验证只请求官方鉴权的 `GetLoginUserInfo`。兼容 `info`／`creator`／`profile`／`user`／直接资料结构；返回身份时必须匹配，正常不返回身份时沿用 Cookie 提供的 ID。空结构、API 拒绝或不匹配不导入账号。未验证中间凭据总会撤销。
6. 保留 `QQ_WEB` 与 `QQ_VERIFY` 的阶段区分，以及安全的 API／HTTP 数字码；不记录 Cookie、原始响应或账号 URL。

### 封面

2026-11-09 匿名发现接口实测返回：

- `music-file.y.qq.com/songlist/...jpg?imageView2/4/w/300/h/300`
- `qpic.y.qq.com/music_cover/.../300?n=1`

旧白名单缺少前一个域名，并拒绝 QQ 图片的所有查询参数，所以图片在下载前就变成占位符。

新版仅允许明确的公共图片域名和已知缩放／缓存查询格式，将缩放参数去掉后使用原图；头像 `q.qlogo.cn/headimg_dl` 保留严格限定的数字身份与尺寸查询。任意 token／vkey 查询、未知域、端口、用户信息、片段仍拒绝，不给图片发送账号 Cookie，也不跟随任意跳转。沿用原有 HTTPS／公网地址检查、字节与解码尺寸上限、取消和内存缓存。

嵌套封面提供大小字段回退，空的嵌套对象不再覆盖可用外层封面。

### 图标

QQ 的上游 1024 矢量画布带有较大透明边距。原先按整张画布缩放到 20 dp，实际标记明显偏小。新版仅对 QQ 按 Path 可见边界等比例缩放、居中到 20 dp；网易云和 B 站保持既有尺寸、颜色与形状。
