# 1.0.0 界面卡死与启动优化

用户反馈 0.9.7 之后的版本打开界面卡住，但全局快捷键仍然可以控制播放；进入网易云、QQ 音乐或登录后也可能触发。提供的堆栈指向侧栏 `DisposableEffect` 清理时的 `NoClassDefFoundError`，随后 Compose 重组协程被取消。

## 原因与修复

0.9.9、0.9.10、0.9.11 的发布包实际均包含报错的 `SaltSidebarToggleContent$Content$2$1$1$1.class`，不是构建漏打包。侧栏使用 Kotlin 的 Java Map `forEach`，编译器把其中的回调生成单独的类；清理回调首次执行时才尝试加载这个类。模组更新／卸载关闭旧 PF4J 加载器后，旧界面仍可能在下一次重组或页面切换中被清理，此时加载器已不能从旧包读取尚未加载的类。

自动回归使用真实 `org.pf4j.PluginClassLoader`、真实 Compose 离屏场景和发布包中的侧栏类，先创建界面并渲染，再关闭加载器，最后销毁场景。0.9.11 发布包复现了与用户完全相同的缺类名称和 `onDispose` 堆栈。1.0.0 将恢复和清理中的 Map 回调改为直接遍历，清理不再创建这个延迟加载的插件类；相同回归通过。已有侧栏渲染回归继续覆盖真实原生标题栏、按钮显隐和布局恢复。

1.0.0 也包含 0.9.10 的窗口框架执行后观察钩子，保留原生 Windows 消息回调的 Compose remember 位置，避免在已有窗口上启用／更新模组时重装回调。该修复背景见 [0.9.10 记录](WINDOW_INPUT_FIX_0.9.10.md)。

## 启动优化

此前 `ExperimentalPlugin.start()` 同步完成账号控制器与目录初始化、持久歌单读取、宿主反射探测、Windows 媒体身份注册和全部 UI／视频钩子安装；这些工作阻塞宿主等待模组启动的调用链。

现在 `start()` 只建立本次生命周期并提交一个守护后台任务。Salt 可以继续创建和处理界面，初始化完成后插件入口可用。初始化尚未完成时点击插件设置或操作按钮只提示当前状态，避免界面线程再等待初始化锁。

若侧栏先于配置就绪，配置交接会在界面线程补一次首页观察，保留用户选择的启动平台／恢复上次页面；原生导航回归覆盖了先出现导航器、后提供配置的顺序。

初始化与停止使用同一生命周期锁。停止会取消尚未执行的初始化；已经执行的初始化先退出，插件再清理资源，确保 PF4J 关闭加载器之前不会留下仍在加载插件类的启动任务。正常初始化和异常退出均关闭启动执行器，不保留轮询线程。回归用阻塞夹具确认启动已返回、AWT 仍能执行任务，同时覆盖提前停止、旧任务取消及缺类错误处理。

旧 `.track` 歌单记录恢复改用与批量 `.tracks` 相同的封面身份预留方式，减少每条记录对同一根目录和封面文件的重复检查；真正访问封面／音轨时仍检查路径，并保留原来的队列身份和已有封面。

## 验证范围与更新

完整本地构建包含 92 个插件回归入口、核心策略、宿主 UI ABI 和产物隔离检查。新增回归使用真实 PF4J 和宿主 Compose；账号、歌单和上游请求使用隔离目录与合成数据。默认构建仍关闭真实桌面窗口、鼠标操作及屏幕帧率采样，不把未执行的前台窗口检查写作通过。

本次没有重启用户正在使用的播放器或读取真实账号。后台启动测试验证阻塞工作离开宿主启动／AWT 调用链，未宣称在所有机器上缩短固定秒数。已有加载器失效或重组协程取消的旧进程，需要完整退出 Salt 后再启动 1.0.0；不用删除账号、歌单或播放器配置。

此版本同时保留 [0.9.11 QQ 音频、封面与桌面测试修复](PLAYBACK_CI_FIX_0.9.11.md)。
