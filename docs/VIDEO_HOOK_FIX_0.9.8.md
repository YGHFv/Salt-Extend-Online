# 0.9.8 视频按钮恢复与宿主钩子修复

0.9.7 将 Compose 界面方法注册为普通方法钩子。Salt 1.19.3 明确拒绝
带 `Composer` 参数的普通方法钩子，视频初始化随之回滚，右上角视频
按钮也被移除。此前测试直接使用方法转换器，绕过了宿主的注册校验，
因此未发现该错误。

0.9.8 改用宿主支持的界面替换与追加接口。播放页和 MiniPlayer 的
外部调用带有非零默认参数掩码，宿主会跳过这些调用的替换；现在挂到
默认参数处理完成后的界面入口。原始底部布局、背景点击回调和整页
展开／收起动画继续由 Salt 管理。普通方法钩子仅用于无 `Composer`
参数的原生状态读取，沿用宿主允许的对象修改和跳过行为。

窗口框架保持固定的组合调用位置，避免切换主题时重建整个播放页，
让旧视频表面的回收释放新表面使用的原生资源。深色主题仅作用于
窗口按钮和播放控件，保留同一视频会话。

视频模式下鼠标静止 3 秒，播放控件、视频按钮、全屏按钮和 Windows
窗口按钮一起隐藏，移动鼠标恢复。窗口按钮隐藏时，同步清空 Windows 原生
按钮命中区域，禁用隐藏按钮的点击。视频收起后恢复原有
窗口主题，重新展开时恢复视频控件主题。

视频区域左键单击暂停／继续歌曲，静音视频跟随音频状态和进度；右键、
拖动和底部控件操作不触发画面单击。底部控件保留原生位置，点击背景
收起整个播放页并保留视频会话，再次展开后继续视频模式。

回归夹具对每一个钩子执行安装版宿主的签名解析和默认参数分析，并在
独立测试 JVM 内应用原始界面调用转换器与普通方法转换器。插件注册
上下文和音频动作使用测试数据，点击仍经过生产的播放器反射调用。
真实 MainWindow 标题栏、Windows 播放页和 Direct3D 视频
窗口验证控件位置、隐藏恢复、单击暂停、原生收起／展开、窗口缩放与
异常退出。测试使用合成视频和隔离配置，不依赖用户平台账号。

保持固定视频帧缓冲与原生线程回收方案；构建沿用单项超时、独立日志
和专用 Windows runner 的守护机制。
