# 1.0.2 诊断日志导出

模组配置最下面新增 **导出诊断日志**。点击后在后台生成 UTF-8 文本文件，保存到用户目录下的 `Downloads\Salt-Extend-Diagnostics`，完成提示显示文件名。每次导出创建新文件，连续点击时只运行一个任务；写入失败会给出固定提示，不展示可能包含私密内容的异常消息。不会打开测试窗口或重新启动播放器。

## 导出内容

- 模组／宿主版本、Java 主版本、CPU 数量、启动与适配器接入状态。
- 原生 UI 接入状态、分发／选择／渲染计数、视频默认分辨率及缓存上限。
- 各平台登录阶段，例如 `QQMUSIC phase=LOGGED_IN credentials=qqcookie`，不读取凭据、账号资料或二维码。
- 间隔约 120 ms 的两次线程快照，包括 JVM 线程 ID、状态、等待的线程 ID、阻塞次数、调用栈和持锁位置。AWT 事件队列使用固定角色名，其余线程只显示数字 ID，原始线程名不进入文件。
- `%APPDATA%\Salt Player for Windows\logs.txt` 最近最多 4 MiB 的安全投影：保留可核对的异常类别／调用栈和日志级别。日志不存在或不可读时仍导出上述即时诊断，并记录固定说明。

## 隐私边界

不复制原始日志，也不序列化设置文件、账号文件、播放队列、登录快照或环境变量。所有自由文本默认移除，包括异常消息、昵称、账号 ID、Cookie 值、令牌、QR 内容、请求／签名媒体地址和本地路径。来源路径与导出绝对路径也不写入文件。

被过滤的内容使用固定字符：QQ `qqcookie`、B站 `bilicookie`、网易云 `neteasecookie`、Apple Music `applecookie`、酷狗 `kugoucookie`；未识别的 Cookie 使用 `cookie`，令牌／账户类字段使用 `account-data`，其他未知正文使用 `private-data`。平台关键词和有限次数的 URL 解码只决定占位符，不决定是否保留正文。因此未知字段、JSON 嵌套、换行、Base64、错误编码和无法识别的平台仍不会直接进入文件。

栈帧中的类和方法必须与已安装程序的 class 文件元数据一致，才会输出。读取元数据不初始化类、不执行宿主代码、不解析方法参数类型；来源文件名、行号、模块／加载器前缀均移除。伪造类名、方法名或把秘密放进文件名的栈帧不能引入任意输出。异常名称同样需要核对程序符号，异常消息始终过滤。这会减少文字上下文，但保留用于分析缺类、线程等待和 Compose 重组的主要程序位置。

写入过程中临时文件也只含安全投影；完成后再移动成 `.txt`。取消或失败清理临时文件，模组停止后不再发布完成通知。读取限制为 4 MiB、单行最多 8 KiB、最多 65,536 行，超限显示截断标记。线程快照最多保留 512 个线程，每个最多 64 层栈。

## 验证

`SafeDiagnosticLogTest` 使用合成日志验证平台占位符、嵌套／多行／双重 URL 编码／Base64、未知字段、路径、签名地址、畸形 UTF-8、伪造栈帧及随机输入的隐私边界，并验证不会触发类静态初始化、不会改写源文件、能从超大日志末尾保留异常。

`DiagnosticExportTest` 验证实际生成的文件不含合成账号数据、包含真实 Compose／PF4J 程序符号和两次 AWT 线程快照；后台工作阻塞时事件队列仍可响应。还覆盖重复点击、没有宿主日志、目录写入失败、停止取消和临时文件清理。配置／包验证要求导出按钮位于最后。

完整构建继续执行实际宿主 ABI、原生 UI、播放与缓存回归。用户真实卡顿时的现场日志仍需用户点击导出后提供文件；本次测试不读取或导出真实账号资料。
