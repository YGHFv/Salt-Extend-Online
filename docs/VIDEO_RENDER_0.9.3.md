# 0.9.3 视频渲染修复

0.9.2 点击视频按钮后会在 Salt 1.19.3 的实际窗口中崩溃。
宿主的 mpv Compose 视频组件仍读取旧 `Direct3DRedrawer` 和 `contextHandler`，
而当前 Skiko 使用 `Direct3DRenderer`，其上下文字段已经变更。
旧组件在 Canvas 绘制期间抛出未捕获异常。仅更新 Java 反射字段仍不足：
宿主原生视频纹理共享代码对 Skiko DirectXDevice 的布局检查也会失败。

插件视频画面改用宿主提供的 D3D11 像素读取入口，后台读取帧并交给当前
Compose 画布绘制，避免旧纹理共享代码。画面读取保持单个待发布帧，
最高 1280×720、25 次／秒，保留视频比例；上游仍选取最高 1080p 的 AVC，
画面显示时按此上限缩放。像素仅保存在内存，不写临时图片文件。
该兼容路径会增加 GPU 到 CPU 的复制开销，暂不提供原生共享纹理的性能。

关闭视频、换歌或卸载前先停止画面读取，再释放原生播放器。
创建、读取或绘制失败会在当前绘制结束后退出视频模式并提示重试，
异常不会直接传入 Salt 的窗口绘制流程。音频继续由 Salt 控制。
视频按钮改为矩形画面中带播放三角的图标，位置继续位于 Salt 全屏按钮左侧。

新增实际 ComposeWindow 回归，使用 Salt 安装包中的 Skiko 默认 Direct3D
渲染器。六秒 AVC 视频先蓝后红，通过插件本机 HTTP 通道播放；屏幕像素
确认视频画面显示、拖动进度后从蓝色变为红色、窗口缩放后仍正确显示。
还验证注入绘制失败后退出视频并显示提示，窗口没有未捕获异常。
此测试不修改 Salt 的现有进程、配置、账号或播放队列文件。
真实平台账号的视频仍需实机验收。
