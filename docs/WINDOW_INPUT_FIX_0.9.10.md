# 0.9.10 更新后窗口点击修复

0.9.9 已处理视频会话锁和独立胶囊背景，但启用或更新模组后，普通页面
仍可能完全收不到鼠标点击。实际运行中的播放器界面线程可以继续处理任务，
当前歌曲并未请求视频，说明问题不局限于视频播放或三秒隐藏计时器。

窗口框架原先使用 `replaceComposable`，然后从替换内容反射调用原函数。
这会改变宿主窗口样式器的 Compose remember 分组。在已经创建的窗口上
启用模组时，原生 `ComposeWindowProc` 和 `SkiaLayerWindowProc` 再次安装，
新回调记录旧回调的地址，但旧样式器已退出组合，回调对象可能被回收。
Windows 消息继续转发到失效地址，导致按钮点击无法进入 AWT/Compose。
实际进程中也观察到新回调保留的前驱地址已无对应的 JNA 回调对象。

窗口框架现在改为 `afterComposable`，仅在原函数执行后通过 `SideEffect`
读取窗口属性。原函数、remember 分组和原生消息回调都保留原来的调用位置。
窗口按钮仍由独立的 caption 内容钩子控制隐藏与恢复。

原回归仅覆盖在创建测试窗口前已启用全部钩子的场景。现在先让真实 Windows
窗口在钩子内容未启用时创建，再通过重组反复启用和停用钩子五次，检查窗口
和绘图画布的 WndProc 地址均保持不变，然后继续执行视频与原生按钮点击回归。
相同的新测试在 0.9.9 类文件上因回调地址改变而失败，0.9.10 通过。
测试使用宿主的真实解析器和转换器、合成播放数据及隔离配置；插件注册分发
仍由测试夹具提供，不能替代所有宿主加载器场景的验证。

验证通过：93 项视频界面／窗口生命周期检查、18 项视频会话检查、79 项
连续帧与音频时钟检查，以及宿主 UI ABI 和产物隔离检查。

从受影响版本更新后，必须完整退出并重新启动 Salt Player。已经失效的
原生前驱回调不能通过仅停用旧模组或重新组合界面可靠恢复。无需删除账号、
歌单或播放器配置。
